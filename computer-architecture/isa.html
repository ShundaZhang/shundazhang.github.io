Read bytes, integers and addresses

A register value is a bit pattern. Instructions and software give the pattern meaning. In an 8-bit teaching ALU, 0xff + 1 wraps to 0x00 with an unsigned carry. In two’s complement, 0xff means −1, so this same addition has no signed overflow. Conversely 0x7f + 1 overflows the signed range while producing 0x80.

Byte order tells you how a multibyte value is laid out. In a little-endian setup, storing 0x12345678 places 78 56 34 12 at consecutive addresses, lowest address first. The examples here assume the common little-endian x86-64 and RV64 Linux environments.

ISA, ABI and platform

An ISA specifies instructions, architectural registers, exceptions and ordering guarantees. The ABI adds conventions for calls, stack layout and binary interfaces. A platform defines components and discovery rules such as interrupt controllers, firmware tables and buses. Microarchitecture is how a specific core implements the ISA.

Trace the same C function

The following examples use the System V AMD64 and RISC-V psABIs. The pointer arrives in rdi or a0, and the result returns in rax or a0. The routines read one 64-bit value and add one modulo 2⁶⁴.

uint64_t next(const uint64_t *p) { return *p + 1; }

x86-64 (AT&T)                 RV64I
movq (%rdi), %rax             ld a0, 0(a0)
addq $1, %rax                 addi a0, a0, 1
ret                           ret  # jalr x0, 0(ra)

The x86 CALL places the return address on the stack. A typical RV64 call writes the link register ra, which a non-leaf function may save. The loads can fault and both cores may satisfy them from cache. Use retired instructions and measured time when comparing different binaries.
