Start with an explicit performance model

For one thread over a measured region, CPU time is retired instructions × average CPI ÷ average cycle rate, using consistent definitions for counters and time. At 2 billion instructions, CPI 1.2 and 3 GHz, that is 0.8 s of CPU time. Elapsed time can also include scheduling, I/O and waiting. Compare latency, sustained throughput and CPU time separately.

Amdahl’s law gives total speedup 1/((1−p)+p/s) when fraction p of baseline time improves by factor s. If 80% improves 4×, the total speedup is 2.5×. Roofline limits throughput by min(peak compute, bandwidth × arithmetic intensity). At 50 GB/s and 2 FLOP/byte, the bandwidth ceiling is 100 GFLOP/s at the stated memory boundary.

Use counters to test a hypothesis

perf stat -r 5 -e cycles,instructions,branches,branch-misses -- ./program

Availability and semantics depend on the PMU and kernel. Check perf list, CPU affinity, frequency policy, and counter multiplexing. Event names and retired instruction counts are not necessarily comparable across an x86 and a RISC-V system. Record workload, compiler, CPU, counters and run-to-run variation alongside the result.
