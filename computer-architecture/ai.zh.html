CPU 和 GPU 的设计为何不同

方面CPUGPU
执行大核心处理多样控制流，重点缩短少量线程的完成时间。大量 lane 分组维持运算单元利用率，NVIDIA CUDA 把线程组织为 warp。
隐藏延迟用乱序调度、分支预测和缓存挖掘线程内部的并行。一组 warp 等待时可发射其他就绪 warp，分支分歧会降低 lane 利用率。
数据复用通过硬件缓存和向量、矩阵指令复用附近数据。kernel 组织相邻访存并做分块，可在寄存器或片上共享内存中复用。

部分 x86 CPU 增加了 Intel AMX 一类分块矩阵操作。RISC-V 可选的 V 扩展提供感知向量长度的指令，可用于 CPU 侧计算。SoC 也可以通过设备接口把 RISC-V CPU 与专用加速器搭配。加速器的执行模型由其自身设计决定。

先算权重和 KV 状态，再选内存

KV bytes = 2 × layers × KV heads × head dimension
             × bytes per element × cached tokens per sequence × sequences

32 layers × 8 KV heads × 128 dimensions × 2 B × 2 (K and V)
= 128 KiB per token and sequence
32,768 tokens → 4 GiB per sequence → 32 GiB for 8 sequences

这是传统 attention 在请求等长且 K、V 精度固定时的有效载荷。使用分组查询注意力时，公式取 KV 头数，它可以少于查询头数。权重另算，例如 700 亿参数、每参数 2 字节约占 140 GB（130.4 GiB），还要预留运行时缓冲与分配开销。量化、共享、分片和序列长度都会改变实际占用。

PagedAttention 按块管理 KV 状态，请求可逐步增长，无需提前预分配最大长度的连续空间，兼容的前缀也可共享块。这与虚拟内存分页有相似之处，块的尺寸和放置由推理运行时管理。

平台如何扩大可用内存

方案实例改变什么
增加 GPU 本地带宽与容量AMD MI355X 单加速器规格为 288 GB HBM3E。NVIDIA 公布 Rubin 单 GPU 配置为 288 GB HBM4，并在 2026 年发布了平台生产公告。更多热点状态可留在计算附近，多 GPU 模型分片仍受互连流量约束。
CPU–GPU 一致性内存AMD MI300A 把 x86 Zen 4 核心与 CDNA 3 GPU 放入同一封装，共享一致的 128 GB HBM3。合适的缓冲区可由双方访问，减少显式拷贝。局部性、一致性与同步仍影响成本。
主机扩容或池化CXL Type 3 内存设备扩展主机可寻址内存，后续 CXL 互连可配合交换机与管理软件实现一定形式的池化。更大或可共享的容量层便于做数据放置，但延迟与带宽取决于链路和拓扑。

统一虚拟地址空间、共享物理内存、硬件缓存一致性和运行时页迁移是不同属性，平台可以只提供其中一部分。CXL 4.0 是已发布规范，实际支持范围由主机、设备、交换机、固件和 OS 共同决定。

2026 年的 Vera 主机 CPU 展示了这类负载怎样影响 CPU 设计。NVIDIA 将 CPU 侧 LPDDR5X、GPU 侧 HBM4 和 CPU–GPU 一致性互连放在同一平台。主机承担运行时、数据搬运与编排，GPU 执行张量密集计算。系统需要决定把带宽、低延迟访问和一致性放在哪一侧。

把计算移到更靠近数据的位置

近存计算把逻辑放在内存附近，例如逻辑裸片或控制器。数字 PIM 可在 DRAM bank 内部或附近放置运算单元。另一些存内计算研究则在存储阵列内运算，包括模拟方案。不同设计对编程、精度、数据布局和验证的要求各不相同。

三星 HBM-PIM 演示了把运算靠近 DRAM 数据的做法。评估具体算子时，应核对支持的操作、操作数布局、跨 bank 的流量及与 CPU、GPU 的同步方式。高片上复用的密集运算、带宽受限的向量运算与容量受限的推理，可能适合不同设计。
