Build a datapath for one load

Start with a register file, PC, ALU, multiplexers and memory interface. Control logic uses the decoded opcode to select data sources and enable writes. For RV64 ld rd, imm(rs1), read rs1, sign-extend the immediate, add them, request eight bytes, and route the returned value to rd when the instruction completes successfully.

A dependent add after a load may need a stall in this pipeline because data becomes available late. Bypassing forwards a result directly to a dependent stage when timing allows. Port conflicts cause structural hazards, unresolved branches cause control hazards, and a branch misprediction squashes younger instructions.

From in-order pipelines to out-of-order cores

Renaming removes false WAR and WAW name dependencies. A true RAW dependency remains. The reorder buffer tracks completion and supports in-order retirement. Load/store queues track addresses and ordering, and a load can receive data from an older matching store. A retired store may still wait in a buffer before it becomes visible to other cores.

Many modern x86 cores decode instructions into micro-operations. RISC-V is implemented by small in-order cores and by out-of-order cores such as BOOM. Predictors, queue sizes and issue width are implementation choices. A misprediction restores the architectural path and may leave microarchitectural traces in caches or predictors.
