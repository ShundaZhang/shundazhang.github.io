虚拟机技术全景

虚拟机向 Guest 操作系统提供一套机器接口。分别沿执行、内存和 I/O 路径，理解它如何使用真实硬件。

概念职责具体例子
Hypervisor / VMM控制虚拟 CPU 状态、地址空间和设备访问，具体实现可将工作分布在内核与用户态。KVM 在 Linux 内核中提供虚拟化能力，QEMU 提供机器模型与设备后端。
硬件辅助虚拟化通过 CPU 虚拟化扩展运行兼容的 Guest 指令，并拦截选定操作。Intel VMX、AMD SVM、RISC-V H
模拟执行软件实现目标 CPU 和机器，可运行与宿主 ISA 不同的系统。QEMU TCG 可在 x86 宿主模拟 RISC-V Guest。
半虚拟化Guest 通过感知虚拟化的接口与宿主协作。Virtio 驱动、半虚拟化时钟可与硬件辅助 CPU 执行配合。
虚拟机管理层创建虚拟机、配置设备并协调生命周期操作。libvirt / virsh / virt-manager

Type 1 通常指直接位于硬件层的 Hypervisor，Type 2 指运行在宿主操作系统上的 VMM。理解 Linux/KVM 时，可以进一步拆开内核虚拟化与用户态设备组件，查看实际边界。

从配置到 Guest 启动

  • 配置。管理层选定 CPU 模型、内存、固件与设备后端，QEMU 进程分配 Guest RAM 的后备内存。
  • 创建。KVM_CREATE_VM 创建 VM 句柄，VMM 登记 memory slot、创建 vCPU 并初始化状态。
  • 启动。固件或直接内核启动路径拉起 Guest OS，Guest 枚举虚拟硬件并加载驱动。

CPU 虚拟化

vCPU 由可保存的架构状态和可调度的执行上下文构成。普通 Guest 计算可直接在 CPU 上持续执行。

架构执行控制内存与中断支持
Intel x86 VMXVMM 使用 VMX root，Guest 使用 non-root，两者各自具有特权环。VMCS 保存 Guest/Host 状态及控制项，配合 VMLAUNCH / VMRESUME 和 VM exit。EPT 完成 GPA 到 HPA 的转换。APIC 虚拟化和 posted interrupt 可减少部分中断开销。
AMD x86 SVMVMCB 记录 Guest 状态与拦截控制，VMRUN 进入 Guest，被拦截的操作使控制权返回 VMM。Nested Page Tables（NPT）提供第二阶段地址转换。
RISC-V H 扩展HS 模式管理运行在 VS/VU 模式的 Guest，通过虚拟 supervisor CSR 与陷入路由提供 Guest supervisor 环境。vsatp 管理 VS-stage，hgatp 管理 G-stage。通过 Hypervisor CSR 和适用的中断扩展注入虚拟中断。

Guest syscall 通常从 Guest 用户态进入自己的内核。事件满足虚拟化控制项配置时才触发退出，切换时须保持寄存器、中断及相关控制状态一致。

  • AMD64 APM · System Programming

内存虚拟化

Guest 管理进程页表，Hypervisor 控制 Guest 物理内存到宿主物理页的映射。

  • 嵌套页表遍历。Guest 页表项位于 GPA，读取这些页表项也需要第二阶段转换。TLB 缓存组合后的转换结果，可减少重复遍历。
  • 两类缺页。第一阶段映射无效时，由 Guest OS 处理 Guest page fault。第二阶段映射或权限有问题时，可触发 EPT violation 或 RISC-V guest-page fault，交由 Hypervisor 处理。
  • 影子页表。VMM 维护 GVA 到 HPA 的组合映射，跟踪 Guest 页表更新。硬件辅助两阶段分页则由 CPU 完成嵌套转换。
  • 修改映射需失效缓存。重新分配宿主页时，需要清除受影响的缓存转换。架构提供 INVEPT / INVVPID、RISC-V HFENCE 等机制。

在常规用户态 VMM 中，宿主虚拟地址 HVA 定位 GPA 对应的后备内存，KVM memory slot 将 Guest 地址范围关联到该内存。HVA 属于宿主进程视图，CPU 第二阶段转换最终选中的是宿主物理页。

设备与 DMA

虚拟设备需要编程接口、数据路径和完成通知。设备直通还需要约束 DMA 能访问哪些内存。

方式数据路径工程取舍
设备模拟Guest 驱动访问模拟硬件寄存器，例如虚拟 e1000 网卡。可复用已有设备驱动，开销包括寄存器模拟和退出。
VirtioGuest 前端与宿主后端通过共享 virtqueue 交换缓冲区。需要兼容的 Guest 驱动，批处理与通知抑制可降低开销。
VFIO 直通Guest 使用被分配的物理设备或 PCIe function。需检查 IOMMU 隔离、设备复位与宿主分组，设备状态也影响迁移支持。
SR-IOV物理功能 PF 创建多个虚拟功能 VF，可分别分配给 Guest。Guest 共享物理硬件资源，固件、单 VF 能力和隔离行为取决于设备。

vhost 可将支持的 Virtio 后端处理移到内核；vhost-user 使用独立用户态后端进程，通过控制通道配置共享内存与队列。它们优化的是 I/O 处理的位置。

  • OASIS Virtio 1.2
  • QEMU vhost-user protocol
  • Linux VFIO
  • Linux SR-IOV guide

磁盘与快照

Guest 看到逻辑扇区，宿主将其映射到文件、块设备或网络存储后端。

Raw 镜像的格式元数据较少；qcow2 增加 cluster 分配、引用计数与写时复制。稀疏镜像随写入分配宿主空间，删除 Guest 文件后能否回收宿主空间，取决于 discard 及整个存储路径的支持。

捕获状态能够恢复什么一致性
磁盘快照某一时刻的磁盘内容运行中的 Guest 可能仅达到崩溃一致性，文件系统冻结与应用协调可提高一致性。
内存与设备状态CPU 寄存器、RAM 和支持的虚拟设备状态恢复时须配套匹配的磁盘状态与兼容虚拟机配置。
备份按恢复方案保留的独立副本验证恢复、保留策略及依赖完整性，外部服务另有自己的状态。

持久性还取决于 Guest flush 请求、宿主缓存与存储后端。快照恢复本地状态，先前已发出的网络消息或已提交的外部事务仍有其效果。

模式包如何转发查看位置

调度与性能

结合 CPU 利用率、资源竞争、内存局部性和 I/O 队列分析性能，每台 VM 都需要实际物理资源。

机制原理观察指标
vCPU 调度典型 QEMU/KVM 中，vCPU 在宿主线程中运行，多个可运行 vCPU 可能竞争物理 CPU 时间。支持时查看 Guest steal time，并观察宿主调度延迟、绑核与 SMT 竞争
NUMA 放置将 Guest 内存靠近执行它的 CPU 放置，Guest 拓扑与宿主分配相匹配。远端内存访问、带宽及跨节点放置
大页满足对齐及后备内存条件时，Guest 或 Host 阶段的大页映射可降低 TLB 压力。TLB miss、内存碎片及大页池余量
气球与超分Guest balloon 驱动按指示交还可用 Guest 页，宿主承诺的内存可能超过当前实际余量。Guest 内存压力、swap 延迟和宿主 OOM 风险
KSM已登记的相同页可合并为一个写保护宿主页，写入时再复制。ksmd CPU 开销、共享页数量与跨租户去重策略
队列与线程调优Virtio 多队列与 I/O 线程可将处理分布到多个核心。队列深度、中断率、p95/p99 延迟和后端饱和情况

vCPU 被暂停调度或迁往其他宿主时，虚拟时钟需要保持连续。KVM clock 接口与 TSC 虚拟化帮助 Guest 获取一致的时钟，定时器递送延迟仍会影响时延敏感应用。

  • Linux KSM

迁移与嵌套

迁移将一台机器的运行状态转移到其他宿主，嵌套虚拟化则在 Guest 内运行另一个 Hypervisor。

脏页产生速率接近有效传输速率时，pre-copy 可能难以收敛。Post-copy 更早恢复目标端，按需拉取缺失页，因此存在依赖源端的阶段。迁移还须兼顾 CPU 特性、设备后端兼容及外部网络身份。

平台与 microVM

根据 Guest、设备与管理接口选择技术栈，各平台对底层机制有不同的组合方式。

技术栈组件与用途先读什么
QEMU / KVM / libvirtLinux 虚拟化，结合硬件执行、灵活设备模型与 VM 生命周期管理。先理解 KVM 的 vCPU 执行和 QEMU 的机器 / 设备模型。

隔离边界

追踪哪些组件处理 Guest 可控输入，以及哪些身份可以管理虚拟机。

  • Guest 到宿主接口。设备描述符、模拟寄存器、共享目录、Guest agent 和管理 API 都包含解析或授权逻辑。按工作负载收紧启用设备与后端权限。
  • 管理面与保存状态。保护 QMP / libvirt 端点、镜像、快照与迁移通道，保存的 RAM 可能包含有效凭据和客户数据。
  • 共享微架构。Guest 可能竞争缓存、预测器与内存带宽，需要按隔离要求配置调度、CPU 缓解措施和租户放置。
  • 机密虚拟机。TDX、SEV-SNP 在各自威胁模型下保护 Guest 私有状态，抵御特权宿主。远程证明及设备共享规则进一步扩展了虚拟化设计。

专题详解可继续阅读 TEE、CPU 侧信道或 Agent 隔离。

以下练习使用装有 QEMU/KVM 的 x86-64 Linux 宿主，将虚拟机配置与测量结果一起记录。

观察宿主与已有虚拟机

lscpu
ls -l /dev/kvm
qemu-system-x86_64 -accel help
virsh -c qemu:///system list --all
virsh -c qemu:///system dominfo lab-vm
virsh -c qemu:///system dumpxml lab-vm
virsh -c qemu:///system domstats lab-vm

通过 Linux 发行版软件包安装 QEMU 与 libvirt，将 lab-vm 换为已有虚拟机名，并使用有权访问对应 libvirt 连接的账号。记录 CPU 模型、vCPU 数、内存后备、网卡模型与存储格式。

用独立增量盘启动练习 VM

准备已关机的 x86-64 Linux qcow2 启动镜像 base.qcow2，镜像须配置串口控制台并采用适当启动模式。示例使用默认 x86 固件，以下命令在当前目录创建新的增量盘。

qemu-img info base.qcow2
qemu-img create -f qcow2 -F qcow2 -b base.qcow2 work.qcow2
qemu-system-x86_64 \
  -accel kvm -cpu host -smp 2 -m 2048 \
  -drive file=work.qcow2,format=qcow2,if=virtio \
  -nic user,model=virtio-net-pci \
  -nographic

增量盘中的 base.qcow2 相对路径基于增量盘所在目录解析，需保留该基础镜像。示例使用 QEMU 用户态网络，其宿主路径与上方桥接图不同。仅支持 UEFI 的镜像需另配匹配固件。默认串口复用配置下，可用 Ctrl-a x 退出 QEMU。

用观察结果检验理解

  • 在宿主找到 QEMU vCPU 线程，解释 Guest 启动 CPU 密集任务后发生的变化。
  • 检查 Guest 块设备和网络驱动，找出 Virtio 设备并与宿主配置对应。
  • 关闭 Guest 后，用 qemu-img info --backing-chain work.qcow2 查看依赖链，解释虚拟容量与宿主实际占用的区别。
