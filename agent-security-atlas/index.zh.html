运行隔离

先确定运行什么代码、谁能提供代码，以及代码可能接触哪些租户的秘密和运行状态。

隔离边界机制与适用场景必须检查的配置
进程 / Linux 容器Namespace 隔离资源视图，cgroups 限定配额，seccomp 与 LSM 收窄内核访问。适合可控且接受共享宿主内核的负载。非特权运行，收紧 capabilities 和挂载，禁止访问容器运行时 socket。
gVisorSentry 在用户态实现 Linux syscall 接口并代理宿主操作，适用配置下由 Gofer 协助访问文件系统。测试 syscall 与文件系统兼容性，并检查外部网络策略和直接文件访问配置。
MicroVM / Kata独立 Guest 内核隔离不可信原生代码和浏览器。Firecracker 与 Cloud Hypervisor 使用硬件虚拟化，Kata 将 VM 边界接入容器工作流。检查 VMM API、共享设备、文件系统桥接、宿主补丁及销毁流程，并测量冷启动、内存和 I/O。
V8 Isolate / WASM语言运行时用内存和 API 边界限制所支持的代码，适合短任务，可只开放类型化函数或受限的 WASI 句柄。检查宿主 imports、预开放目录、网络 fetch、执行预算与运行时版本，确认厂商叠加的隔离边界。
机密 VM / TEETDX 和 SEV-SNP 在其威胁模型内保护 Guest 私有状态。远程证明可用于向符合度量策略的工作负载发放密钥。按需验证 CPU / GPU 证明链，继续限制工具权限与共享 I/O，并明确哪些服务仍接触明文。

哪些商用产品用了 TEE

TEE 的采用有多广？

机密计算已经用于商用 AI。Linux Foundation 2026 年 11 月发布的调查显示，其采用范围仍小于网络与访问隔离、VM 内的容器和 microVM 沙箱。

工具权限、审批与出口策略控制 Agent 能做什么。即使 Agent 跑在 TDX 中，恶意网页诱导它向未经授权的地址发送客户数据时，仍需出口策略拦截请求。TEE 的额外用途是约束有特权的基础设施读取正在处理的明文或密钥，并通过远程证明把数据与密钥交付绑定到通过验证的工作负载。因此，机密推理、敏感数据处理和密钥托管是典型应用。

工具与凭据

Harness 把拟执行的动作交给网关，由网关检查当前用户、Agent、目标、操作和数据类别。

  • 最小权限。 在服务端解析资源，对读写分别授权，并核对对象归属和租户。写操作和导出审批绑定规范化后的目标、参数、用户、有效期及幂等键。
  • 网络出口。 默认拒绝。允许的流量经代理转发，在可见时检查主机、端口、路径和方法。重定向与解析后的 IPv4 / IPv6 地址逐跳复核，阻断元数据服务、私网及链路本地地址，按需单独开放指定私有服务。测试 UDP、替代 DNS 和浏览器间接外联。
  • 凭据代理。 授权后签发短时、绑定接收方的令牌，由代理注入获准的上游请求。凭据不进入 Shell 环境和对话。过滤响应中回显的请求头与签名链接，跨源重定向时剥离凭据。
  • MCP。 审查并固定服务器和工具定义，验证 token audience，并为上游 API 单独获取 OAuth 授权。禁止透传客户端令牌。本地 stdio 服务器以受限权限运行，远端调用由模型之外的策略授权。
  • 浏览器会话。 公开检索与已登录操作使用独立浏览器配置。限制上传下载，重定向后检查目标，登录输入和改变外部状态的操作由受控交互处理。

混淆与数据

混淆可以指多类机制。安全属性取决于变换的对象、谁可以还原，以及策略由哪一层执行。

技术用途局限
分隔与 Spotlighting标记外部文本来源和边界，或编码文档，让配套模型按数据处理。Microsoft 记录了一种采用 Base64 的做法。它是面向模型的提示信号。编码可逆、消耗上下文并可能影响任务效果，操作权限仍需外部执行。
脱敏 / 假名化剔除不需要的字段，对需要关联的标识符使用租户或任务级代号，将映射保存在网关，授权后再解析。上下文和重复代号仍可能重新识别身份。单一正则容易漏过 OCR、代码或多语言变体，还要检查日志与工具结果。
秘密占位符把句柄或占位符交给沙箱。外部代理只为获准的请求替换成真实凭据。还要限制远端操作。有效令牌仍可能被用于非预期写入，响应也可能回显真实凭据。
信息流控制跟踪来源与污点在变换中的传播。分离不可信解析和有权工具规划，在数据出口授权。CaMeL 研究用 capability 将这些约束绑定到数据流。研究中的保证依赖受测运行时和策略模型。需明确处理未追踪路径、解密级和模型派生数据。
密码学机密性传输用 TLS，持久状态用封装加密。需要抵御宿主时，使用经证明的密钥发放。收到明文的模型和工具仍可能经写操作或网络泄露。对所有明文出口执行目标策略。

策略评估前可归一化 Unicode、HTML、Markdown、URL 编码和 OCR，并保留原始来源及分类。攻击者也会用这些形式隐藏指令。Base64、改写提示词、隐藏系统提示和存储加密各自需要独立的权限校验配合。

Google Cloud

Gemini Enterprise Agent Platform 在独立的 Google 托管 gVisor 沙箱中执行代码，沙箱不继承父 Agent Runtime 的凭据。GKE 的 Agent Substrate 为每个 Actor 分配 SPIFFE 身份，并可在出口网关注入凭据。Agent Sandbox 则使用 Kubernetes 原生控制器与工作负载网络策略。

Kubernetes 部署需核对请求的 RuntimeClass 与节点实际运行时。比较 microVM 和 gVisor，并验证哪些身份可读取或恢复持久状态。

Cloudflare Agents / Code Mode

Dynamic Workers 运行生成的 JavaScript，按需提供受限 bindings。需要 Linux 工具和依赖时可选容器。Dynamic Worker 可单独配置网络出口。

globalOutbound: null

这是 Worker Loader 的配置项。省略会继承父 Worker 的网络出口权限。

显式设置 globalOutbound。设为 null 时，通过批准的 bindings 提供所需能力，并逐一核对它们能否写入、导出或转授。

Vercel Sandbox

每个沙箱使用 Firecracker microVM。VM 外的防火墙支持网络策略，可向匹配的 HTTPS 请求注入头部，也可把请求转发到自有代理。

const sandbox = await Sandbox.create({
  networkPolicy: 'deny-all',
});

创建时关闭网络，工作负载确有需要时再开放通过审查的端点。

文档给出的默认值是 allow-all，应显式设置策略。共享 API 主机上的操作权限过宽时，在代理层检查具体请求。

部署设计

以客服 Agent 为例：它需要读客户记录、查看公开帮助中心并拟写回复。公开浏览与客户数据访问走独立路径。

  • 创建。 固定运行镜像与工具版本。为绑定租户的任务分配隔离工作区，只挂载必要输入。新建与恢复都校验同一策略，并配置任务有效期、配额、递归上限。
  • 约束。 原始凭据和客户记录读取留在沙箱外。沙箱只取得必要工作区与网络路径。禁止公开导出工单派生数据，发信前审批具体收件人和正文。
  • 审计与撤销。 记录租户、会话、发起者、工具、规范化目标、策略版本和判断。尽量减少正文日志，关联沙箱、MCP 与网络出口事件。使令牌过期、清除临时数据，并按租户 ACL 保存获准产物。
  • 验证拒绝路径。 在模拟敏感数据里放入标记值，测试私网地址、DNS 与重定向绕过、允许域名上的未授权上传、重放审批、敏感工具结果和跨租户恢复快照。分别衡量正常任务完成率与恶意副作用阻断率。
