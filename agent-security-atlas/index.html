Threat model

A cloud agent crosses trust boundaries whenever it reads a document, reuses state, runs code, or acts under a user’s identity.

Entry pointExample failureWhere to enforce
Documents / web / RAGA webpage tells a support agent to paste a private order into a search query.Tag origins and constrain data sent to public search.
Tools / MCP / subagentsA tool response requests a second call with broader permissions.Authorize each action independently with identity, resource and argument checks.
Code and browserA dependency reads mounted secrets or a logged-in browser transfers data.Separate code and browser profiles, restrict files and network, keep secrets in a broker.
Memory / snapshotsPoisoned memory persists or a restored image exposes another tenant’s state.Enforce tenant ACLs on retrieval, writes, snapshot restore and deletion.
Supply chain / runaway loopsA new skill adds an executable or a retry loop repeats a costly write.Pin and review packages, bound depth/cost, and make writes idempotent.

How widely are TEEs used?

Confidential computing is already used in commercial AI, but it was less common than network and access isolation, containers in VMs, and microVM sandboxes in the Linux Foundation’s November 2026 survey.

Tool permissions, approvals and egress checks govern what an agent can do. If a webpage persuades a TDX-protected agent to send customer data to an unapproved destination, the egress policy must still block that request. A TEE addresses a separate threat: privileged infrastructure reading plaintext or keys in use. Remote attestation can make data and key delivery conditional on a verified workload, which is why confidential inference, sensitive data processing and key custody are useful early applications.

Use a separate boundary for each mutually untrusted tenant or job. Bind the session ID to an authenticated owner, make base images read-only, give the job a writable scratch layer, then revoke credentials and destroy it. A warm pool should assign clean instances. For hibernation, protect snapshots like live memory and scope the restore operation to the same tenant and policy version.

Tools & credentials

Have the harness send proposed actions to a broker that checks the current user, agent, destination, operation and data class.

  • Capabilities. Resolve targets server-side. Authorize reads and writes separately, including object ownership and tenant. For a write or export, bind the approval to the normalized destination, parameters, user, expiry and an idempotency key.
  • Egress. Default to deny. Route allowed traffic through a proxy that can enforce host, port, path and method where visible. Revalidate redirects and resolved IPv4/IPv6 addresses. Block metadata, private or link-local destinations except named private services. Test UDP, alternate DNS and browser side channels.
  • Credential broker. Mint a short-lived, audience-bound token after authorization, then inject it into the approved upstream request. Keep it out of the shell environment and transcripts. Filter echoed headers and signed links from responses, and remove credentials on cross-origin redirects.
  • MCP. Review and pin servers and tool definitions, validate token audiences, and get separate upstream OAuth authorization. Deny token passthrough. Run local stdio servers under constrained privileges and authorize remote calls outside the model.
  • Browser sessions. Use separate profiles for public research and authenticated work. Restrict uploads and downloads, check the destination after redirects, and put login input and state-changing actions under controlled user interaction.

Obfuscation & data

The term obfuscation spans several techniques. Their security properties depend on what is transformed, who can reverse it and where policy is enforced.

TechniqueUseLimit
Delimiters / spotlightingTag source boundaries and mark untrusted tokens, or encode document text for a trained/instructed model to read as data. Microsoft documents a base64 variant.Model-facing hint. Encoding is reversible, consumes context and can affect utility. Enforce permissions externally.
Redaction / pseudonymsRemove irrelevant fields and replace needed identifiers with tenant- or task-scoped aliases. Keep the alias map in the broker. Resolve only after authorization.Context and repeated aliases can re-identify people. A regex alone misses OCR, code and multilingual variants. Test log and tool-result handling too.
Secret placeholdersPass a handle or placeholder into the sandbox. An external proxy exchanges it for a credential only on the permitted request.Scope remote operations as well as hosts. A valid token can still enable unwanted writes, and a response could echo a real secret.
Information-flow controlTrack provenance and taint across transformations. Separate untrusted parsing from privileged tool planning, and authorize data flows at sinks. CaMeL explores capability-backed data flows.Research guarantees apply to the studied runtime and policy model. Untracked paths, declassification and model-derived data need explicit treatment.
Cryptographic confidentialityUse TLS for transport, envelope encryption for persisted state, and attested key release when the workload must be protected from the host.A model or tool receiving plaintext can still leak it through writes or network calls. Apply destination policy to every plaintext sink.

Normalize Unicode, HTML, Markdown, URL encoding and OCR before policy evaluation, while retaining the original source and classification. Attackers can hide instructions that way too. Avoid treating base64, rephrasing, hidden system prompts or encrypted storage as authority checks.

Product practices

The controls below come from public product documentation reviewed on 15 November 2026. Hosted features and availability depend on compute mode, region, plan and release.

Amazon Bedrock AgentCore

Serverless Runtime microVMs isolate CPU, memory and filesystem per session. Gateway Policy can evaluate Cedar rules for tool calls. Use IAM or JWT authentication and bind session IDs to the invoking tenant.

AWS also documents an Instances compute type that can host multiple collaborating agents with a shared filesystem. Check the chosen compute type and whether persistent filesystem configuration retains state after termination.

Google Cloud

Gemini Enterprise Agent Platform executes code in a separate Google-managed gVisor sandbox without inheriting the parent Agent Runtime credentials. On GKE, Agent Substrate uses per-actor SPIFFE identity and an egress gateway that can inject credentials. Agent Sandbox uses Kubernetes-native controllers and workload network policy.

For the Kubernetes path, check the requested RuntimeClass and the actual node runtime. Compare microVM versus gVisor, and test who can read or restore persisted state.

Cloudflare Agents / Code Mode

Dynamic Workers run generated JavaScript with a restricted set of bindings. A separate container option supports Linux tools and packages. The dynamic Worker can have its own outbound behavior.

globalOutbound: null

This is a Worker Loader option. Omission inherits the parent Worker’s outbound access.

Set globalOutbound explicitly. With null, give the worker access only through approved bindings. Review those bindings for write, export and delegation capabilities.

Claude Managed Agents

Cloud environments accept limited networking and an explicit host list. Vault credentials can be restricted to HTTPS request headers for specific hosts, with placeholders visible to sandbox code.

networking:
  type: limited
  allowed_hosts:
    - help.example.com

Place this fragment under the cloud environment’s config. The hostname is illustrative.

Review remote MCP, web search and web fetch settings separately. Allowed hosts can still accept uploads. Put sensitive reads and writes behind application tools that enforce operation-level rules.

OpenAI Agents API / ChatGPT Agent

An OpenAI-hosted Agents API sandbox supports restricted networking and vault-backed credential injection. Self-hosted sandbox owners maintain their execution and network boundaries. ChatGPT Agent separately documents user confirmations and observation controls for its product workflows.

Keep network rules and credential restrictions in place when enabling automatic review. Audit sandbox, remote MCP and application-hosted tools as separate outbound routes.

Vercel Sandbox

Each sandbox uses a Firecracker microVM. The external firewall supports network policies and can inject HTTP headers on matching outbound HTTPS requests or forward traffic to your proxy.

const sandbox = await Sandbox.create({
  networkPolicy: 'deny-all',
});

Create with a closed network, then allow reviewed endpoints when the workload needs them.

Set a policy explicitly because the documented default is allow-all. Use request-level checks for shared API hosts where domain-level authorization is too broad.

Docker Sandboxes

This developer-side example uses a microVM per sandbox and an external credential proxy. Shared folders and other exposed interfaces define what the agent can access.

The Docker security model places local stdio MCP servers on the host. Treat their installation and execution permissions as a separate boundary from commands running in the VM.

  • Provision. Pin runtime images and tools. Allocate one isolated workspace to a tenant-bound job and mount only the required input. Gate cold startup and restore on the same policy. Set task TTL, quotas and recursion limits.
  • Constrain. Keep raw credentials and customer record lookups outside the sandbox. Give the sandbox a narrow workspace and network path. Disallow public export of ticket-derived data. Require review before sending the exact message.
  • Observe and revoke. Log tenant, session, proposer, tool, normalized target, policy version and verdict. Minimize payload logging. Correlate sandbox, MCP and egress events. Expire tokens, discard temporary data, and retain approved artifacts under a tenant ACL.
  • Verify failure paths. Use canary strings in fake data. Probe private IPs, DNS and redirect bypass, an allowed host with an unauthorized upload, stale approval replay, sensitive tool output and wrong-tenant snapshot restore. Compare legitimate task completion and blocked malicious effects.
